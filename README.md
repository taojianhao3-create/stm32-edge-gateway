# 工业物联网边缘网关 V2.0

基于 **STM32F411CEU6 + FreeRTOS + LVGL** 开发工业级边缘网关，完成功能迭代，新增**Flash分区管理、系统日志、日志浏览、独立看门狗、故障自复位、低功耗、MQTT自动重连**，具备传感器采集、本地可视化、云端上报、断网缓存&自动补传全链路能力，适配工业现场7×24小时无人值守场景。

> ### 项目说明
>
> 本工程为完整的工业级边缘网关固件，从底层驱动到应用层任务均由本人设计与实现，
> 开发过程全程使用 Git 管理（历史可见仓库 commit 记录）。
>
> **几个主要设计点**：
>
> | 方向 | 实现要点 |
> |:---|:---|
> | **RTOS 架构** | 基于 FreeRTOS 原生 API 划分 5 个任务；任务声明按职责拆分为 `app_tasks.h`（任务入口）与 `app_data.h`（共享数据与常量） |
> | **AT 联网** | 建链做成**分片状态机**（`net_sm.c`），每片 ≤50ms，避免阻塞式 AT 指令把任务卡住 26.5s |
> | **看门狗** | **签到制**喂狗：4 个任务各签一位、全齐才喂，可发现单个任务卡死；并用 **TIM5_CH4 输入捕获实测 LSI** 校准超时 |
> | **数据通路** | 采集侧统一投递 UI 与 MQTT 两个队列（双队列解耦），断网时界面照常刷新 |
> | **低功耗** | **FreeRTOS tickless idle**（RTC 作唤醒源 + FreeRTOS/HAL 双重 tick 补偿） |
> | **RS485 时序** | 发送完成等 TC 再切方向，而非固定延时（避免末字节被截断） |
>
> ⚠️ 使用前请把 Wi-Fi 与巴法云凭据替换成自己的
> （见 `ESP8266/net_sm.c` 的 CWJAP 步骤与 `ESP8266/pal.h`）——仓库中均为占位符。

## 软件架构
### FreeRTOS 任务划分
| 任务 | 优先级 | 栈大小 | 核心职责 |
|:---|:---:|:---|:---|
| UI任务 | AboveNormal | 1024 | LVGL界面刷新、页面跳转、息屏控制 |
| 传感器任务 | Normal+1 | 512 | Modbus多从机轮询采集 |
| MQTT任务 | Normal | 512 | 数据上报、离线缓存、自动补传 |
| 网络任务 | Normal | 512 | 心跳检测、自动重连 |
| 看门狗任务 | Highest | 512 | 定时喂狗，故障自复位 |

### 任务同步机制
- 消息队列：传递传感器数据、UI刷新指令
- 互斥锁：保护串口、Flash等共享资源，防止并发冲突
- 全局状态标志：标记网络在线/离线状态

## 核心功能（V1基础 + V2新增）
### 1. Modbus-RTU 协议（手写实现）
- 支持多从机轮询，适配温湿度、光照传感器，可灵活扩展设备；
- 实现**CRC16查表算法**，搭配双超时机制，保证总线通信稳定；
- 直接操作串口寄存器收发数据，规避HAL库阻塞问题。

### 2. MQTT 3.1.1 协议（手写裸协议）
- 手动封装连接、订阅、发布、心跳全套二进制报文，无第三方依赖；
- 基于ESP8266透传模式对接**巴法云MQTT平台**；
- 新增**心跳检测+自动重连**，网络异常自动恢复连接。

### 3. AT 建链状态机（阻塞式改造，V2 重点）
原实现的建链是一串阻塞式 AT 指令，单次调用最坏要 **26.5~31.5 秒**
（`CWJAP`/`CIPSTART`/`CIPSEND` 各 5 秒超时，外加两次 `AT+RST` 与多处硬延时），
带来三个问题：独占 AT 任务、把看门狗超时顶到 IWDG 的硬件上限（32.8 秒）之外、
长时间占住串口锁导致 MQTT 发不出数据。

改造为 **`net_sm.c` 命令表 + 分片执行**：
- 四种步骤：`CMD`（发 AT 指令 + 分片收应答 + 匹配关键词）、
  `ESCAPE`（发 `+++` 后静默 1 秒退出透传）、
  `BLOB`（透传下直接发二进制报文，如 MQTT CONNECT）、
  `RECV_AT`（等 CONNACK，非文本按字节判）；
- 调用方每 **50ms** 驱动一次 `NetSm_Slice()`，**片内拿锁、片外放锁**；
- 每片结束调用签到接口，看门狗只需容忍 50ms；
- 静默时间用**时间戳比较**替代 `vTaskDelay`，全程不阻塞；
- CONNACK 用**滑动扫描**匹配（`CIPSEND` 会回显 `>`，按固定偏移读会错位）。

**效果**：最长阻塞 **26.5s → 50ms**；看门狗超时得以从"被迫 ≥32 秒"收到 **20 秒**。

### 4. SPI Flash 分区管理（V2核心新增）
将8MB W25Q64划分为两个独立分区，各司其职：
1. **4MB 运行日志区**
   统一日志接口，分级记录设备运行、网络、异常事件；日志循环覆盖，LVGL页面**倒序查看**（新日志置顶）。
2. **4MB 离线缓存区**
   基于**环形缓冲区+魔术字**实现断电续写；断网自动存数据，重连后**分批自动补传**；数据上报后仅修改标记实现逻辑删除，减少Flash擦除损耗。

### 5. 独立看门狗 & 故障自愈（V2新增，已改造为"签到制"）
- 片内 IWDG 独立看门狗，**超时 20 秒**；Dog_task 每 **1 秒**检查一次；
- **签到制**：UI / Modbus / MQTT / AT 四个任务各自跑完一轮签到自己那一位，
  只有 **4 位全齐**才真正喂狗。**任一任务卡死就不喂**，IWDG 到期把整机复位
  —— 能发现"单个任务死掉"，而不只是"整机停摆"；
- **未喂时会记录缺失位图**（如 `WDG miss bits=0x0C (MQTT,AT)`）并写入 Flash 日志，
  复位后仍可读，用于现场定位究竟是哪个任务卡住；
- **超时精度**：LSI 是 IWDG 的时钟源，精度极差（F4 上芯片间跨度约 17~32kHz）。
  用 **TIM5_CH4 输入捕获**以 HSE 派生的 100MHz 时钟为尺子实测本芯片真实 LSI 频率，
  再反算分频与重装载值，使超时精确等于 20 秒；
- 系统卡死、任务死锁时**自动硬件复位**，满足工业 7×24 小时运行要求。

### 6. 低功耗（V2新增，已实现 tickless idle）
- **智能息屏**：设备 10 秒无数据/触摸动作自动关闭 LCD 背光；数据更新或触摸时自动亮屏；
- **FreeRTOS tickless idle**：空闲时停掉 tick 中断，由 **RTC 唤醒定时器**在
  "下一个任务到期之前"把 CPU 叫醒，避免每 1ms 无谓唤醒（空闲 1 秒：1000 次唤醒 → 1 次）；
  - 唤醒源为什么用 RTC：SysTick 属 Cortex-M 内核，进 Sleep 后内核时钟停、**无法唤醒自己**；
    RTC 由独立 LSE 驱动，低功耗下天然存活；
  - **双重 tick 补偿**：FreeRTOS tick 与 HAL tick（TIM4 挂 APB1，睡眠时也会停）
    都要补，否则 `HAL_GetTick()` 冻结会导致**日志时间戳累积丢时间**；
  - 睡眠用 **Sleep 模式**（只停内核时钟，USART/SPI 时序不受影响），不碰 Stop 模式。

### 7. LVGL 图形界面（V2新增日志页）
- 主界面：传感器数据、进度条、设备状态、运行时长实时展示；
- 新增**日志浏览页面**，支持页面切换、触摸交互；
- 自定义中文字体，控件按需刷新，优化CPU占用。

## 常见问题与解决方案
| 问题现象 | 解决方案 |
|:---|:---|
| Modbus数据异常 | 核对RS485 A/B线，增加终端电阻 |
| MQTT连接失败 | 重新核算报文长度，检查WiFi/平台配置 |
| 意外自动复位 | 提高喂狗任务优先级，保证正常喂狗 |
| 日志无显示 | 上电初始化日志写指针，校验魔术字 |
| 串口死锁 | 规范互斥锁使用，避免嵌套加锁 |
| 息屏无法唤醒 | 动作触发时重置空闲计时、点亮背光 |

## 快速使用
1. **硬件接线**：严格对照引脚表接线，所有模块共地，ESP8266独立供电；
2. **固件要求**：ESP8266烧录标准AT固件，STM32使用Keil/STM32CubeIDE编译烧录；
3. **平台配置**：注册巴法云，修改代码内WiFi信息、设备UID与主题；
4. **运行测试**：上电自动联网采集、上传数据；断网自动缓存，重连自动补传；点击日志按钮查看运行记录。
